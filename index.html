#0. Общие сведения о стенде

#0.1. Что требуется сделать (кратко по заданию)

Необходимо построить корпоративную сеть предприятия на двух маршрутизаторах под OpenWrt (R1 и R2), рабочей станции и сервере на ОС «Альт». В рамках Модуля А выполняются следующие группы задач:

  • Сеть: статическая и динамическая адресация, DHCP-сервер, выход в интернет через NAT, связность сегментов через динамическую маршрутизацию OSPF.
  • Безопасность периметра: зоны межсетевого экрана (WAN, CAMS, SERVERS, TUNNEL, ADMINS, PRINTERS), правила доступа между зонами и явная блокировка всего остального.
  • Видеонаблюдение: ZoneMinder на SRV — камеры, зоны детекции, раздельные сроки хранения, русский интерфейс, хранилище в /srv/video.
  • Печать: CUPS на ADMIN-PC — сетевой принтер, журналирование, пользователь, отдельный каталог логов.
  • Резервное копирование: Кибер Бэкап на SRV — организация IRPO, отделы и пользователи, план копирования каталога /etc рабочей станции.
  • Мониторинг: Zabbix на SRV (порт 8080) — добавление SRV и ADMIN-PC, агенты, статус Available.

#1. Физическая подготовка оборудования

#1.1. Состав стенда

  • 2 × маршрутизатор Cudy (под прошивку OpenWrt) — это R1 и R2;
  • 1 × сервер (ПК/мини-ПК или ВМ) с ОС «Альт Сервер 11» — SRV;
  • 1 × ПК с ОС «Альт Рабочая станция 11» — ADMIN-PC;
  • 2 × IP-камеры с поддержкой RTSP — cam1, cam2 (либо устройства-источники RTSP, см. раздел 8.11);
  • 1 × сетевой принтер — print;
  • патч-корды (минимум 7 шт.), управляющий ноутбук с SSH-клиентом, доступ к интернет-аплинку площадки.

#1.2. Прошивка маршрутизаторов Cudy в OpenWrt

Важно про Cudy: заводская прошивка проверяет подпись и не даёт залить «чужой» образ напрямую. Поэтому прошивка делается в два этапа: сначала ставится промежуточный (intermediate) образ OpenWrt от самой Cudy, который снимает проверку подписи, а затем — официальный образ OpenWrt с сайта проекта.

#1.2.1. Определите модель и аппаратную ревизию

  • Посмотрите точную модель и ревизию (v1/v2/v3) на наклейке снизу роутера и в заводском веб-интерфейсе.
  • Ревизия важна: образы OpenWrt привязаны к конкретной ревизии флеш-памяти. По наклейке также проверьте серийный номер (SN).
ВНИМАНИЕ — новая флеш-память на свежих партиях

На роутерах Cudy линейки AX3000 (например, TR3000), выпущенных с ноября 2025 г. (SN начинается с 2543 и выше), стоит новая флеш-память F50L1G41LC. Для них нужен OpenWrt не ниже 24.10.5 — старые образы не загрузятся и «окирпичат» устройство. Мы ставим OpenWrt 25.12, поэтому требование выполнено, но НЕ заливайте на такие модели старые версии.

#1.2.2. Скачайте две прошивки

Файл A — промежуточный образ OpenWrt от Cudy (снимает проверку подписи). Скачивается со страницы загрузки OpenWrt на сайте Cudy:

https://www.cudy.com/en-us/blogs/faq/openwrt-software-download

Файл B — официальный образ OpenWrt 25.12 под вашу точную модель. Берётся в «OpenWrt Firmware Selector» (введите модель — получите ссылки):

https://firmware-selector.openwrt.org/

  • В селекторе нужен Sysupgrade-образ.
  • Актуальная стабильная версия на момент подготовки — OpenWrt 25.12 (внутри неё используйте самый свежий минорный релиз, например 25.12.4). Важно: в 25.12 пакетный менеджер — apk, а не opkg. Это учтено в разделах по FRR/OSPF.

#1.2.3. Этап 1 — промежуточный образ (через заводской интерфейс)

  • Подключите ноутбук патч-кордом к LAN-порту Cudy. Откройте заводской веб-интерфейс (адрес на наклейке, часто http://192.168.10.1).
  • Перейдите в «Advanced» → «System» → «Firmware Upgrade» и загрузите файл A (промежуточный OpenWrt от Cudy).
  • Дождитесь перезагрузки. Роутер перейдёт на промежуточный OpenWrt; адрес сменится на 192.168.1.1 (LuCI).
ПРОВЕРКА / СОВЕТ — проверка после этапа 1

Откройте http://192.168.1.1 — должен открыться LuCI (интерфейс OpenWrt). Если ПК не получил адрес 192.168.1.x — обновите аренду DHCP (вынуть-вставить кабель) или задайте статический 192.168.1.2/24.

#1.2.4. Этап 2 — официальный образ OpenWrt 25.12

  • В LuCI откройте «System» → «Backup / Flash Firmware».
  • В разделе «Flash new firmware image» нажмите «Flash image…» и выберите файл B (официальный sysupgrade 25.12).
  • ОБЯЗАТЕЛЬНО снимите галочку «Keep settings» («Сохранить настройки»).
  • Нажмите «Flash» и дождитесь перезагрузки (2–3 минуты). Не выключайте питание во время прошивки.
  • Повторите этапы 1–2 для второго роутера. Прошивайте по одному: оба роутера сразу после прошивки имеют один и тот же адрес 192.168.1.1.

#1.2.5. Первый вход и пароль root

  • Подключите ноутбук к LAN-порту роутера, получите адрес 192.168.1.x.
  • Через LuCI (http://192.168.1.1) задайте пароль root: «System» → «Administration» → «Router Password». Либо по SSH (на свежем OpenWrt вход без пароля), затем команда passwd.
ssh root@192.168.1.1
# затем на роутере:
passwd
ПОДКЛЮЧЕНИЕ ПО SSH — первичный доступ к R1/R2 (до настройки сети)

На этом этапе оба роутера доступны на 192.168.1.1.

Команда подключения: ssh root@192.168.1.1

Если ранее уже подключались к этому адресу (другой ключ хоста) — сбросьте старый ключ:

ssh-keygen -R 192.168.1.1

#1.4. Управляющий ноутбук

  • Для первичной настройки каждого роутера подключайте ноутбук к LAN-порту этого роутера (получите 192.168.1.x по DHCP).
  • После смены адресов на «боевые» вы переподключаетесь к роутеру уже по новому адресу. Удобнее всего подключить ноутбук в нужный сегмент и задать статический IP. Конкретные адреса для переподключения указаны в фиолетовых SSH-блоках разделов 3 и 4.
  • На ноутбуке используйте любой SSH-клиент (встроенный ssh в Windows/Linux, PuTTY и т. п.).

#2. Подключение к устройствам по SSH (общие принципы)

#2.1. OpenWrt (R1, R2)

  • SSH-сервер — Dropbear, порт 22, пользователь root. После задания пароля (раздел 1.2.5) вход по паролю.
  • Подключение: ssh root@<адрес_роутера>.
  • После переадресации/перепрошивки сбрасывайте старый ключ хоста: ssh-keygen -R <адрес>.
ВНИМАНИЕ — чтобы не «потерять» SSH после смены сети

По умолчанию Dropbear может быть привязан к интерфейсу lan. Так как мы перестраиваем сеть, явно снимем привязку, чтобы SSH слушал все интерфейсы (команда есть в разделе 3.5). Это типичная причина «пропавшего» SSH после удаления интерфейса lan.

#2.2. ОС «Альт» (SRV, ADMIN-PC)

  • Сервер OpenSSH; служба называется sshd. Конфиг на «Альт» лежит в /etc/openssh/sshd_config (не в /etc/ssh).
  • Для входа под root по паролю в /etc/openssh/sshd_config должны быть PermitRootLogin yes и PasswordAuthentication yes.
  • Подключение: ssh root@<адрес>. Установка/включение службы — в разделах 6.3 и 7.3.

#2.3. Камеры и принтер

  • IP-камеры и сетевой принтер настраиваются через их собственные веб-панели (адрес устройства в браузере). SSH у них, как правило, нет.
  • Задайте на камерах адреса 172.16.10.10 и 172.16.10.20, на принтере — 172.16.100.100 (через их панели). Если используете программные RTSP-источники — см. раздел 8.11.

#3. Настройка R1 (OpenWrt)

Граничный маршрутизатор. Имеет выход в интернет (WAN), сегменты камер и серверов, линк до R2. На нём выполняются: адресация, NAT, зоны firewall (WAN/CAMS/SERVERS/TUNNEL), OSPF.

ПОДКЛЮЧЕНИЕ ПО SSH — к R1 на старте настройки

Ноутбук — в любой LAN-порт R1; WAN-порт R1 — в интернет-аплинк (нужно для установки пакетов).

Подключение: ssh root@192.168.1.1

В конце раздела (после применения сети) R1 переедет на боевые адреса — переподключение описано в шаге 3.9.

#3.1. Проверьте наличие интернета на R1

Пакеты FRR ставятся из сети, поэтому WAN-порт R1 уже должен быть в интернете. Проверка:

ping -c2 8.8.8.8

#3.2. Имя устройства (FQDN)

uci set system.@system[0].hostname='r1'
uci commit system
echo 'r1.au.team' > /proc/sys/kernel/hostname
# зафиксируем FQDN в hosts:
grep -q 'r1.au.team' /etc/hosts || echo '127.0.1.1 r1.au.team r1' >> /etc/hosts

#3.3. Определите имена сетевых портов (DSA)

В современном OpenWrt порты коммутатора видны как отдельные устройства (DSA): обычно lan1 lan2 lan3 lan4 и wan. Сверьтесь со своей моделью:

ip -br link
ls /sys/class/net/
ВНИМАНИЕ — имена портов зависят от модели

Если у вас вместо lan1..lan4 показаны другие имена (например, eth0/eth1 или phy0-ap0 для Wi-Fi) — подставляйте реальные имена портов в конфиги ниже. На физическом Cudy беспроводные интерфейсы нам не нужны; используем только проводные LAN-порты и WAN.

#3.4. Сеть и IP-адреса

Перестраиваем /etc/config/network. Команда ниже целиком перезаписывает файл (один раз вставьте весь блок в SSH). При других именах портов — поправьте значения ports и device.

cat > /etc/config/network <<'EOF'
config interface 'loopback'
        option device 'lo'
        option proto 'static'
        option ipaddr '127.0.0.1'
        option netmask '255.0.0.0'
config globals 'globals'
        option packet_steering '1'
# WAN — к провайдеру (DHCP)
config interface 'wan'
        option device 'wan'
        option proto 'dhcp'
# Сегмент камер: мост из LAN1 + LAN2 (cam1, cam2)
config device
        option name 'br-cams'
        option type 'bridge'
        list ports 'lan1'
        list ports 'lan2'
config interface 'cams'
        option device 'br-cams'
        option proto 'static'
        option ipaddr '172.16.10.1'
        option netmask '255.255.255.0'
# Сегмент серверов: LAN3 -> SRV
config interface 'servers'
        option device 'lan3'
        option proto 'static'
        option ipaddr '172.16.110.254'
        option netmask '255.255.255.0'
# Линк до R2 (зона TUNNEL): LAN4
config interface 'tunnel'
        option device 'lan4'
        option proto 'static'
        option ipaddr '10.10.10.1'
        option netmask '255.255.255.252'
EOF
ПРИМЕЧАНИЕ — что мы получили

wan — внешний интерфейс (DHCP от провайдера); cams — 172.16.10.1/24 (шлюз камер); servers — 172.16.110.254/24 (шлюз SRV); tunnel — 10.10.10.1/30 (линк до R2). Стандартный интерфейс lan и мост br-lan мы заменили — это намеренно.

#3.5. SSH должен слушать все интерфейсы

Снимаем возможную привязку Dropbear к удалённому интерфейсу lan, иначе после перезапуска сети потеряете SSH:

uci -q delete dropbear.@dropbear[0].Interface
uci commit dropbear

#3.6. Межсетевой экран: зоны и правила

Создаём зоны WAN, CAMS, SERVERS, TUNNEL с политикой по умолчанию REJECT (явная блокировка), затем открываем только то, что требует задание. NAT (masquerade) включается на зоне WAN — это и есть «маскарадинг для SERVERS и TUNNEL» при их выходе в интернет.

cat > /etc/config/firewall <<'EOF'
config defaults
        option syn_flood '1'
        option input 'REJECT'
        option output 'ACCEPT'
        option forward 'REJECT'
config zone
        option name 'wan'
        list network 'wan'
        option input 'REJECT'
        option output 'ACCEPT'
        option forward 'REJECT'
        option masq '1'
        option mtu_fix '1'
config zone
        option name 'cams'
        list network 'cams'
        option input 'REJECT'
        option output 'ACCEPT'
        option forward 'REJECT'
config zone
        option name 'servers'
        list network 'servers'
        option input 'REJECT'
        option output 'ACCEPT'
        option forward 'REJECT'
config zone
        option name 'tunnel'
        list network 'tunnel'
        option input 'REJECT'
        option output 'ACCEPT'
        option forward 'REJECT'
# Доступ к зоне CAMS только для SERVERS (SRV -> камеры)
config forwarding
        option src 'servers'
        option dest 'cams'
# Доступ к зоне SERVERS из TUNNEL (через туннель приходит трафик ADMIN-PC)
config forwarding
        option src 'tunnel'
        option dest 'servers'
# Выход в интернет (NAT) для SERVERS и TUNNEL
config forwarding
        option src 'servers'
        option dest 'wan'
config forwarding
        option src 'tunnel'
        option dest 'wan'
# Разрешить протокол OSPF на линке до R2 (служба для работы маршрутизации в туннеле)
config rule
        option name 'Allow-OSPF-tunnel'
        option src 'tunnel'
        option proto 'ospf'
        option target 'ACCEPT'
# Диагностика: ICMP к роутеру с внутренних зон и из туннеля
config rule
        option name 'Allow-ICMP'
        option proto 'icmp'
        option icmp_type 'echo-request'
        list src 'servers'
        option target 'ACCEPT'
config rule
        option name 'Allow-ICMP-tunnel'
        option src 'tunnel'
        option proto 'icmp'
        option icmp_type 'echo-request'
        option target 'ACCEPT'
# Управление роутером по SSH из сегмента серверов и из туннеля
config rule
        option name 'Allow-SSH-servers'
        option src 'servers'
        option proto 'tcp'
        option dest_port '22'
        option target 'ACCEPT'
config rule
        option name 'Allow-SSH-tunnel'
        option src 'tunnel'
        option proto 'tcp'
        option dest_port '22'
        option target 'ACCEPT'
EOF
ВНИМАНИЕ — если правило OSPF «не применяется»
В некоторых сборках имя протокола ospf не распознаётся. Тогда замените в правилах option proto 'ospf' на option proto '89' (89 — номер протокола OSPF).
ПРИМЕЧАНИЕ — про требования задания по firewall

«Доступ к CAMS только для SRV» — реализовано форвардингом servers→cams (других источников к камерам нет). «Доступ к SERVERS из TUNNEL» — форвардинг tunnel→servers. «Запрет из WAN в CAMS/SERVERS/TUNNEL» — обеспечен политикой WAN forward=REJECT и отсутствием соответствующих форвардингов. «Явная блокировка» — input/forward по умолчанию REJECT во всех зонах.

Правила ICMP/SSH — служебные (для диагностики и удалённого управления). Они не открывают межсегментный транзит и при строгой проверке их можно сузить или убрать.

#3.7. NAT (маскарадинг)

Отдельных действий не требуется: option masq '1' на зоне WAN (см. конфиг выше) включает трансляцию для всего исходящего в интернет, в том числе для разрешённых форвардингов SERVERS→WAN и TUNNEL→WAN. Так выполняется пункт «маскарадинг для зоны SERVERS и TUNNEL».

#3.8. Динамическая маршрутизация OSPF (FRR)

На физическом оборудовании мультикаст OSPF работает нормально (в отличие от некоторых виртуальных стендов), поэтому используем полноценный OSPF через FRR. Ключ аутентификации — abi2026.

#3.8.1. Установка FRR (OpenWrt 25.12 — пакетный менеджер apk)

apk update
apk add frr frr-ospfd frr-vtysh
ПРИМЕЧАНИЕ — если flash маловато

FRR занимает несколько МБ. На большинстве актуальных Cudy памяти достаточно. Если места не хватает, выберите модель с большей flash или используйте extroot.

#3.8.2. Включить демона ospfd

sed -i 's/^ospfd=no/ospfd=yes/' /etc/frr/daemons
/etc/init.d/frr enable

#3.8.3. Конфигурация OSPF на R1

Имя интерфейса в FRR — это имя ядра (порт линка до R2, у нас lan4). Если порт другой — поправьте в двух местах.

cat > /etc/frr/frr.conf <<'EOF'
frr defaults traditional
hostname r1
log syslog informational
!
interface lan4
 ip ospf authentication message-digest
 ip ospf message-digest-key 1 md5 abi2026
!
router ospf
 ospf router-id 10.10.10.1
 passive-interface default
 no passive-interface lan4
 network 10.10.10.0/30 area 0
 network 172.16.10.0/24 area 0
 network 172.16.110.0/24 area 0
 default-information originate
!
line vty
!
EOF
ПРИМЕЧАНИЕ — пояснения к конфигу OSPF R1

router-id 10.10.10.1 — фиксируем явно. passive-interface default + no passive-interface lan4 — соседство устанавливаем только на линке до R2, но все перечисленные сети анонсируются. Ключ MD5 abi2026 (key-id 1) — должен совпадать на R1 и R2. default-information originate — R1 отдаёт в OSPF маршрут по умолчанию, чтобы R2 (и ADMIN-PC) ходили в интернет через R1. Внешние сети в интернет не анонсируются: OSPF на WAN не запущен.

#4.6. DHCP-сервер для ADMIN-PC

Пул 172.16.120.10–172.16.120.200, DNS-суффикс au-team.abi, DNS-сервер 172.16.120.1 (сам R2). Так как WAN не подключён, R2 пересылает DNS-запросы на 8.8.8.8 (через туннель и NAT на R1).

        option domainneeded '1'
        option localise_queries '1'
        option rebind_protection '1'
        option local '/lan/'
        option domain 'au-team.abi'
        option expandhosts '1'
        option authoritative '1'
        option readethers '1'
        option leasefile '/tmp/dhcp.leases'
        option noresolv '1'
        list server '8.8.8.8'
        list server '1.1.1.1'
config dhcp 'admins'
        option interface 'admins'
        option start '10'
        option limit '191'
        option leasetime '12h'
        list dhcp_option '6,172.16.120.1'
        list dhcp_option '15,au-team.abi'
config dhcp 'tunnel'
        option interface 'tunnel'
        option ignore '1'
config dhcp 'printers'
        option interface 'printers'
        option ignore '1'
config odhcpd 'odhcpd'
        option maindhcp '0'
        option leasetrigger '/usr/sbin/odhcpd-update'
        option loglevel '4'
EOF
ПРИМЕЧАНИЕ — про пул

ПРОВЕРКА / СОВЕТ — что должно быть
В «show ip ospf neighbor» сосед в состоянии Full. На R1 видны маршруты на 172.16.120.0/24 и 172.16.100.0/24 (через 10.10.10.2). На R2 виден маршрут по умолчанию 0.0.0.0/0 (через 10.10.10.1) и сети камер/серверов R1.
Если соседства нет: проверьте линк LAN4↔LAN1, совпадение ключа abi2026 и key-id 1, и что правило Allow-OSPF-tunnel применилось (иначе proto '89').

#5.2. Связность между роутерами

# с R1:
ping -c2 10.10.10.2
# с R2:
ping -c2 10.10.10.1

#5.3. Интернет с клиентских устройств

После настройки SRV и ADMIN-PC (разделы 6–7):

  • С SRV: ping -c2 8.8.8.8 — должно проходить (NAT на R1 для зоны SERVERS).
  • С ADMIN-PC: ping -c2 8.8.8.8 — должно проходить (через R2 → R1 → NAT).
  • С ADMIN-PC: ping -c2 172.16.110.50 — доступ к SRV (зона SERVERS из TUNNEL разрешена).
  • С SRV: ping -c2 172.16.10.10 — доступ к камере (SERVERS → CAMS разрешён).

#5.4. Проверка изоляции (что НЕ должно работать)

  • С ADMIN-PC пинг камеры 172.16.10.10 — НЕ должен проходить (к камерам имеет доступ только SRV).
  • Из внешней сети (WAN) недоступны сегменты CAMS/SERVERS/TUNNEL/ADMINS/PRINTERS — это обеспечено политикой WAN forward=REJECT.
ПРИМЕЧАНИЕ — важно

Если изоляция «слишком строгая» и что-то нужное не ходит — сверьтесь со списком форвардингов в разделах 3.6 и 4.7. Не открывайте лишние зоны: задание прямо требует явной блокировки и доступа только по перечисленным направлениям.

#6. Настройка SRV (Альт Сервер 11)

Сервер служб. Адрес 172.16.110.50/24, шлюз — R1 (172.16.110.254). На SRV развернём ZoneMinder, Кибер Бэкап и Zabbix.

ПРИМЕЧАНИЕ — первый доступ к SRV

SRV — сервер (часто без графики). Первичные шаги (сеть, hostname, sshd) выполните в локальной консоли SRV. Во многих сборках «Альт Сервер» служба sshd уже включена — тогда после настройки сети можно сразу подключаться по SSH.

#6.1. Сеть (статический адрес)

«Альт Сервер» использует систему etcnet. Узнайте имя интерфейса и пропишите адрес/шлюз/DNS (DNS = 8.8.8.8, т. к. выход в интернет идёт через NAT на R1):

ip -br link
# подставьте своё имя интерфейса вместо enp1s0:
NIC=enp1s0
mkdir -p /etc/net/ifaces/$NIC
cat > /etc/net/ifaces/$NIC/options <<'EOF'
BOOTPROTO=static
TYPE=eth
DISABLED=no
CONFIG_IPV4=yes
EOF
echo '172.16.110.50/24' > /etc/net/ifaces/$NIC/ipv4address
echo 'default via 172.16.110.254' > /etc/net/ifaces/$NIC/ipv4route
echo 'nameserver 8.8.8.8' > /etc/resolv.conf
systemctl restart network
ПРОВЕРКА / СОВЕТ — проверка сети

ip -br addr — должен быть 172.16.110.50; ping -c2 8.8.8.8 — интернет через R1.

#6.2. Имя хоста (FQDN)

#6.3. SSH

sed -i 's/^#*PermitRootLogin.*/PermitRootLogin yes/' /etc/openssh/sshd_config

ПОДКЛЮЧЕНИЕ ПО SSH — к SRV

С ноутбука (в сегменте серверов) или с R1: ssh root@172.16.110.50

Дальше ZoneMinder/Кибербэкап/Zabbix удобно настраивать по SSH + через веб-браузер.

#8. Видеонаблюдение: ZoneMinder на SRV (подробно)

Разворачиваем ZoneMinder на SRV. Требования задания: часовой пояс Asia/Moscow, камеры cam1 (172.16.10.10) и cam2 (172.16.10.20), зоны детекции, хранение в /srv/video, сроки хранения cam1 — 7 дней, cam2 — 14 дней, русский интерфейс. Доступ к камерам у SRV уже разрешён правилом firewall SERVERS→CAMS.

#8.1. Установка

В репозитории «Альт» есть готовый пакет zoneminder — он сам подтянет MariaDB, Apache (httpd2) и PHP:

apt-get update
apt-get install -y zoneminder
systemctl enable --now mariadb
ПРИМЕЧАНИЕ — если веб сразу заработал — часть шагов 8.2 можно пропустить

Пакет «Альт» обычно сам создаёт БД и конфиги. Сначала попробуйте открыть веб-интерфейс (шаг 8.3). Если он жалуется на БД — выполните ручную инициализацию (8.2).

#8.2. Инициализация БД (если потребуется) и запуск служб

# Создать БД и пользователя ZoneMinder:
mysql -uroot <<'EOF'
CREATE DATABASE IF NOT EXISTS zm;
CREATE USER IF NOT EXISTS 'zmuser'@'localhost' IDENTIFIED BY 'zmpass';
GRANT ALL PRIVILEGES ON zm.* TO 'zmuser'@'localhost';
FLUSH PRIVILEGES;
EOF
# Загрузить схему (найдём файл zm_create.sql автоматически):
ZMSQL=$(find /usr/share -name 'zm_create.sql' 2>/dev/null | head -1)
mysql -uroot zm < "$ZMSQL"
# Прописать доступ к БД в конфиге ZM:
sed -i 's/^ZM_DB_USER=.*/ZM_DB_USER=zmuser/' /etc/zm/zm.conf
sed -i 's/^ZM_DB_PASS=.*/ZM_DB_PASS=zmpass/' /etc/zm/zm.conf
sed -i 's/^ZM_DB_NAME=.*/ZM_DB_NAME=zm/' /etc/zm/zm.conf
# Запуск служб:
systemctl enable --now zoneminder
systemctl enable --now httpd2
ПРИМЕЧАНИЕ — имена могут отличаться
Конфиг ZM на «Альт» обычно /etc/zm/zm.conf. Apache на «Альт» — служба httpd2. Если zm_create.sql не найден — схему создаёт сам пакет при первом запуске; тогда просто запустите zoneminder и откройте веб.

#8.3. Вход в веб-интерфейс

  • Откройте в браузере: http://172.16.110.50/zm
  • При первом входе ZoneMinder может предложить применить обновление БД (Apply) — согласитесь.

#8.4. Часовой пояс Asia/Moscow

timedatectl set-timezone Asia/Moscow
# часовой пояс для PHP (ZoneMinder этого требует):
PHPINI=$(php -i 2>/dev/null | awk -F'=> ' '/Loaded Configuration File/{print $2}' | tr -d ' ')
sed -i 's#^;*date.timezone.*#date.timezone = Asia/Moscow#' "$PHPINI"
systemctl restart httpd2
  • Дополнительно в веб-интерфейсе: Options → System → параметр ZM_TIMEZONE = Asia/Moscow (если присутствует), сохранить.

#8.5. Русский язык интерфейса

  • Options (Настройки) → вкладка Config → найдите параметр ZM_LANG_DEFAULT → установите ru_ru → Save.
  • Либо язык можно задать для текущего пользователя в его профиле (правый верхний угол → пользователь → язык). После сохранения интерфейс станет русским.

#8.6. Хранилище записей в /srv/video

mkdir -p /srv/video
# Владелец — пользователь, под которым работает ZoneMinder (на RPM-системах обычно apache):
chown -R apache:apache /srv/video
chmod 755 /srv/video
  • В веб-интерфейсе откройте управление хранилищами: http://172.16.110.50/zm/?view=storage.
  • Add (Добавить) → Name: video, Path: /srv/video → Save. Это хранилище мы назначим обеим камерам в шагах 8.7–8.8.
ПРИМЕЧАНИЕ — альтернатива через симлинк

Если не хотите создавать отдельное хранилище — можно перенаправить стандартный каталог событий: остановите zoneminder, затем замените /var/lib/zoneminder/events симлинком на /srv/video (chown apache). Но способ через «Storage» в веб-интерфейсе чище и нагляднее.

#8.7. Добавление камеры cam1

  • На главной (Console) нажмите Add (Добавить) — откроется окно настроек монитора.
  • General: Name = cam1; Function = Modect (запись по движению); Enabled — включено.
  • Source: Source Type = Ffmpeg; Source Path = RTSP-адрес камеры, например rtsp://172.16.10.10:554/stream1; Method = TCP.
  • Storage: выберите хранилище video (созданное в 8.6).
  • Save. Монитор cam1 появится в консоли.
ВНИМАНИЕ — RTSP-путь зависит от модели камеры

Часть после адреса (/stream1, /h264, /Streaming/Channels/101, /live и т. п.) у каждого вендора своя. Точный путь смотрите в инструкции/веб-панели камеры. Логин/пароль камеры подставляются в адрес: rtsp://user:pass@172.16.10.10:554/...

Проверить поток до настройки можно с SRV: ffprobe rtsp://172.16.10.10:554/... (или ffplay).

#8.8. Добавление камеры cam2

  • Повторите шаги 8.7 для второй камеры: Name = cam2; Source Path = rtsp://172.16.10.20:554/stream1 (свой путь); Storage = video; Function = Modect.

#8.9. Зоны активации записи (детекция движения)

  • В консоли кликните по имени камеры → вкладка Zones (Зоны).
  • Откройте зону All (создаётся автоматически) → Type = Active, Preset = Medium (средняя чувствительность) → Save. При необходимости мышью задайте полигон нужной области кадра.
  • Повторите для cam2. Теперь запись событий запускается при движении в активной зоне.

#8.10. Сроки хранения: cam1 — 7 дней, cam2 — 14 дней

Раздельные сроки реализуются фильтрами ZoneMinder, которые автоматически удаляют старые события.

#8.10.1. Фильтр для cam1 (7 дней)

  • Откройте http://172.16.110.50/zm/?view=filter (или меню «Filters»).
  • Conjunction: all. Условие 1: Monitor Name equal to cam1.
  • Условие 2 (and): Date/Time less than -7 day (т. е. событие старше 7 дней).
  • Отметьте Delete all matches (Удалять все совпадения) и Run filter in background (Выполнять в фоне). Имя — purge_cam1 → Save.

#8.10.2. Фильтр для cam2 (14 дней)

  • То же самое: Monitor Name = cam2, Date/Time less than -14 day, Delete + Run in background, имя purge_cam2.
ПРИМЕЧАНИЕ — про названия полей

В разных версиях ZoneMinder поле может называться «Date/Time», «Start Date/Time» или просто «DateTime», а относительное значение записывается как -7 day / -14 day. Суть одна: события выбранной камеры старше N дней автоматически удаляются фоновым фильтром.

#8.11. Если реальных камер нет: RTSP-заглушка

Для проверки без физических камер поднимите программный RTSP-источник на устройстве в сегменте камер (адреса 172.16.10.10 и 172.16.10.20). Например, на мини-ПК с Linux:

  • Установите mediamtx (RTSP-сервер) и ffmpeg; зациклите тестовый ролик в RTSP-поток, например rtsp://172.16.10.10:8554/cam.
  • Для двух камер используйте либо два устройства (172.16.10.10 и 172.16.10.20), либо одно с двумя IP-адресами (alias) и двумя путями RTSP. В ZoneMinder укажите соответствующие RTSP-адреса как Source Path.

#8.12. Проверка ZoneMinder

  • В консоли обе камеры (cam1, cam2) показывают изображение, статус не красный.
  • При движении создаются события; файлы появляются в /srv/video.
  • В разделе Filters присутствуют purge_cam1 и purge_cam2; интерфейс — на русском; часовой пояс — Asia/Moscow.

#9. Сервер печати CUPS на ADMIN-PC

Требования задания: установить CUPS и принтер print (172.16.100.100); журналирование (максимум 50 заданий); пользователь print с паролем P@ssw0rd; логи печати в /srv/printerLogs. Доступ ADMIN-PC к принтеру разрешён правилом ADMINS→PRINTERS на R2.

ПОДКЛЮЧЕНИЕ ПО SSH — к ADMIN-PC для настройки CUPS

С ноутбука в сегменте ADMINS: ssh root@172.16.120.X

Веб-интерфейс CUPS будет доступен на http://<адрес ADMIN-PC>:631.

#9.1. Установка CUPS

apt-get update
apt-get install -y cups
systemctl enable --now cups

#9.2. Пользователь print

useradd -m print 2>/dev/null || true
echo 'print:P@ssw0rd' | chpasswd
# право управлять CUPS (группа администраторов печати):
gpasswd -a print lpadmin 2>/dev/null || gpasswd -a print sys
ПРИМЕЧАНИЕ — группа администрирования CUPS
Группа задаётся директивой SystemGroup в /etc/cups/cupsd.conf (часто lpadmin или sys). Если gpasswd с lpadmin не сработал — смотрите SystemGroup в cupsd.conf и добавьте print в неё.

#9.3. Каталог логов и лимит заданий

mkdir -p /srv/printerLogs
chown root:lp /srv/printerLogs
chmod 755 /srv/printerLogs
# лимит заданий = 50 и пути логов в /srv/printerLogs:
sed -i 's#^MaxJobs .*#MaxJobs 50#' /etc/cups/cupsd.conf
grep -q '^MaxJobs' /etc/cups/cupsd.conf || echo 'MaxJobs 50' >> /etc/cups/cupsd.conf
sed -i 's#^AccessLog .*#AccessLog /srv/printerLogs/access_log#' /etc/cups/cupsd.conf
sed -i 's#^ErrorLog .*#ErrorLog /srv/printerLogs/error_log#' /etc/cups/cupsd.conf
sed -i 's#^PageLog .*#PageLog /srv/printerLogs/page_log#' /etc/cups/cupsd.conf
grep -q '^AccessLog' /etc/cups/cupsd.conf || echo 'AccessLog /srv/printerLogs/access_log' >> /etc/cups/cupsd.conf
grep -q '^ErrorLog'  /etc/cups/cupsd.conf || echo 'ErrorLog /srv/printerLogs/error_log'  >> /etc/cups/cupsd.conf
grep -q '^PageLog'   /etc/cups/cupsd.conf || echo 'PageLog /srv/printerLogs/page_log'   >> /etc/cups/cupsd.conf
systemctl restart cups
ПРИМЕЧАНИЕ — MaxJobs

MaxJobs 50 ограничивает число одновременно хранимых заданий в очереди — это и есть «журналирование максимум 50 заданий». Логи доступа/ошибок/страниц теперь пишутся в /srv/printerLogs.

#9.4. Добавление принтера print (172.16.100.100)

lpadmin -p print -E -v socket://172.16.100.100:9100 -m everywhere

cupsenable print

cupsaccept print

lpstat -p print -v

ПРИМЕЧАНИЕ — драйвер/протокол

socket://...:9100 — печать по «raw» TCP (порт 9100), подходит большинству сетевых принтеров. -m everywhere использует драйвер IPP Everywhere. Если принтер не поддерживает IPP — используйте -m raw (сырой поток) либо подберите PPD под модель.

Альтернатива — добавить принтер через веб-интерфейс http://<ADMIN-PC>:631 → Administration → Add Printer (логин/пароль — пользователь print).

#9.5. Проверка CUPS

  • lpstat -p print — принтер enabled, accepting jobs.
  • Тестовая печать: echo test | lp -d print → задание уходит на 172.16.100.100.
  • В каталоге /srv/printerLogs появляются файлы access_log/error_log/page_log.

ПРИМЕЧАНИЕ — связь агента с сервером

Регистрация агента идёт в направлении ADMIN-PC → SRV, что разрешено правилами firewall (ADMINS→TUNNEL→SERVERS). Обратное подключение SRV → ADMIN-PC не требуется.

#10.5. Хранилище и план ADMIN-BACKUP

  • Хранилище: укажите локальную папку /var/backup на сервере управления (SRV) как место хранения резервных копий.
  • Создайте план защиты с именем ADMIN-BACKUP для устройства ADMIN-PC:
  • Что копировать: файлы/папки → /etc;
  • Куда: хранилище /var/backup;
  • Расписание: ежедневно в 00:00;
  • Хранение: последние 5 копий;
  • Примените план к ADMIN-PC.

#10.6. Запуск и проверка

  • Выберите ADMIN-PC → Запустить резервное копирование сейчас.
  • Дождитесь статуса «Успешно»; в /var/backup на SRV появятся файлы копии.

#11. Мониторинг: Zabbix на SRV (порт 8080)

Разворачиваем Zabbix на SRV (веб-интерфейс на порту 8080), добавляем хосты SRV и ADMIN-PC, ставим агентов. Удобнее всего — в Docker (порт 8080 пробрасывается напрямую).

#11.1. Освободите порт 8080

Веб-интерфейс «Альт» (alterator) часто занимает 8080. Проверьте и при необходимости освободите:

ss -tlnp | grep ':8080' || echo 'порт свободен'
systemctl disable --now ahttpd 2>/dev/null || true
systemctl disable --now alteratord 2>/dev/null || true

#11.2. Установка Docker

apt-get update
apt-get install -y docker-ce docker-compose
# если пакетов нет — попробуйте: apt-get install -y docker-engine docker-compose
systemctl enable --now docker
ПРИМЕЧАНИЕ — имя пакета Docker на «Альт»

В разных сборках «Альт» пакет может называться docker-ce, docker-engine или docker-io. Проверьте: apt-cache search docker | grep -i engine.

ПРИМЕЧАНИЕ — если включён межсетевой экран на SRV

Убедитесь, что на SRV открыты входящие порты 8080 (веб) и 10051 (сервер ← активный агент ADMIN-PC). Если на «Альт Сервер» активен firewalld/iptables — добавьте разрешения для этих портов.

#11.4. Агент на SRV (пассивный)

apt-get install -y zabbix-agent
sed -i 's#^Server=.*#Server=0.0.0.0/0#' /etc/zabbix/zabbix_agentd.conf
sed -i 's#^ServerActive=.*#ServerActive=127.0.0.1#' /etc/zabbix/zabbix_agentd.conf
sed -i 's#^Hostname=.*#Hostname=SRV#' /etc/zabbix/zabbix_agentd.conf
systemctl enable --now zabbix_agentd
  • Server=0.0.0.0/0 — приём запросов от любого сервера (требование задания). Контейнер Zabbix-сервера опрашивает агент SRV по адресу 172.16.110.50:10050.

#11.5. Агент на ADMIN-PC (активный — из-за изоляции)

Сервер на SRV не может опрашивать ADMIN-PC пассивно (правила firewall разрешают только обращение ADMIN-PC → SRV). Поэтому агент ADMIN-PC работает в активном режиме — сам отправляет данные на SRV:10051.

apt-get install -y zabbix-agent
sed -i 's#^Server=.*#Server=0.0.0.0/0#' /etc/zabbix/zabbix_agentd.conf
sed -i 's#^ServerActive=.*#ServerActive=172.16.110.50#' /etc/zabbix/zabbix_agentd.conf
sed -i 's#^Hostname=.*#Hostname=ADMIN-PC#' /etc/zabbix/zabbix_agentd.conf
systemctl enable --now zabbix_agentd

#11.6. Добавление хостов и статус Available

  • SRV: Data collection → Hosts → Create host. Host name = SRV; интерфейс Agent = 172.16.110.50:10050; шаблон «Linux by Zabbix agent»; группа «Linux servers». Индикатор Available (ZBX) станет зелёным.
  • ADMIN-PC: Host name = ADMIN-PC (точно как Hostname агента); шаблон «Linux by Zabbix agent active» (активные проверки); группа «Linux servers».
ВНИМАНИЕ — про индикатор Available у ADMIN-PC

Классический зелёный Available (ZBX) загорается от пассивного опроса агента. У ADMIN-PC пассивный опрос со стороны SRV закрыт изоляцией.

Вариант 1 (рекомендуется): активный агент — данные идут, мониторинг работает, ничего открывать не нужно.

Вариант 2 (если по критериям нужен именно пассивный Available): разрешите серверу достучаться до ADMIN-PC:10050 — добавьте на R1 форвардинг servers→tunnel, а на R2 — tunnel→admins (или узкие правила только для порта 10050). Это ослабляет изоляцию — применяйте по требованиям площадки.

#11.7. Проверка Zabbix

  • Оба хоста в списке Hosts; от SRV идут данные (Available зелёный).
  • От ADMIN-PC поступают активные проверки (Latest data заполняется).
  • Веб-интерфейс открывается по http://172.16.110.50:8080.
